# 拾影 v1.0.0 · 发布前动效与交互优化计划

## 目标

发布前最后一次只做“动效与交互”的优化：让每一次点击、滑动、切换都有明确反馈；每个弹窗、抽屉、菜单、页面切换都有完整、灵动、可打断的进出场；整体手感达到“精心打磨”的产品级标准。

## 边界

- 不改业务逻辑、接口、数据库、导入/筛图/导出流程。
- 不改信息架构、文案与既有视觉材质；液态玻璃、标准主题、壁纸、字体保持用户当前设计。
- 不引入第三方动画库；只使用 CSS、Web Animations API、View Transitions。
- 必须尊重 `prefers-reduced-motion` 与设置里的“界面动效：关闭”。
- 低性能/软件渲染环境自动降级，不用大面积模糊动画。

## 基线审计

现有已具备：
- 启动开屏双弧聚拢与 Logo 飞行落位。
- 按钮 pointerdown 缩放、全局点击波纹。
- 页面卡片 wave 入场、滚动卡片 pop。
- 分段选择 choice-slider 滑块弹簧。
- 主题切换 View Transition 圆形揭示。
- 照片查看的 FLIP 飞入飞出。
- Agent 面板、抽屉、详情栏的基础 transition。
- 复核照片滚动入场。

主要缺口：
1. **液态玻璃弹窗没有入场/退场动画**：`showModal()` 对 liquid 直接显示，`closeModal()` 直接 remove；首配弹窗因此是唯一例外。
2. **页面路由切换没有转场**：`runViewTransition` 只用于主题，路由切换是直接替换 DOM。
3. **更多菜单/右键菜单关闭是瞬时的**：只有打开动画。
4. **批量操作栏没有进出场**：多选状态切换时工具栏内容突变。
5. **设置页分区导航没有 active 指示与滚动联动**：点击仅滚动，无持续反馈。
6. **滑块没有轨道填充、拖动/松手反馈**：只有原生 input。
7. **异步操作的全局处理状态不可见**：保存、扫描、AI 等请求期间没有统一“正在处理”反馈。
8. **滚动只有自定义滚动条，没有页面进度/边缘阴影**。
9. **部分 hover/active 反馈不一致**；没有统一 focus-visible 环。
10. **Agent/抽屉/照片详情进出场曲线不统一**，缺少可打断的弹簧感。
11. **Toast 无进度与关闭反馈**，多条堆叠没有上限。
12. **Filter 切换/批量计数等状态变化**没有数字与局部脉冲反馈。

## 统一动效语言

| Token | 值 | 用途 |
|---|---|---|
| press | 100ms | 按下压缩 |
| feedback | 180ms | hover / 局部状态 |
| pop | 300ms | 菜单、卡片、提示 |
| panel | 420ms | 抽屉、Agent、详情面板 |
| modal | 460ms | 弹窗 |
| page | 360ms | 页面切换 |
| spring | cubic-bezier(.16,1,.3,1) | 主入场 |
| overshoot | cubic-bezier(.2,1.18,.35,1) | 小元素弹入 |
| exit | cubic-bezier(.4,0,.2,1) | 退场 |

原则：入场略慢、退场更快；弹窗从触发源方向进入；所有动画只动 transform / opacity / clip-path / filter，避免布局抖动；连续点击可打断上一个动画。

## 工作流

1. 建立 `release-motion.css` 与 `release-motion.js` 动效层，加载在现有样式之后。
2. 修复弹窗：新增 `.modal-inner` 内容层 + `.modal-scrim` 遮罩层；玻璃底同帧出现，内容层负责弹簧入场/退场；首配弹窗保留独立 Q 弹。
3. 页面切换：路由使用 View Transitions；顶栏保持不动，仅页面内容淡入 + 轻微上浮/缩放。
4. 菜单/右键菜单：打开与关闭都走 WAAPI，支持反向打断。
5. 抽屉/详情/Agent/照片详情：统一 spring 曲线、遮罩淡入、内容 stagger。
6. 交互反馈：统一 press class、focus-visible 环、filter 计数脉冲、批量栏 stagger、滑块填充与输出脉冲。
7. 滚动反馈：顶栏下方页面进度条、滚动边缘阴影、设置 section scrollspy。
8. 异步反馈：`api()` 派发请求事件；右上角出现低干扰处理指示；超过 250ms 才显示。
9. 可用性：reduced-motion 全部关停；低性能降级；键盘焦点可见。
10. 回归：所有页面、弹窗、抽屉、菜单、批量、Agent、右键菜单、照片详情截图 + 交互录制。
11. 独立审查：至少 3 个子代理分别从代码实现、浏览器交互、设计/可用性三个角度检查；任何一项未通过都回到实现，直到 3 个都认可。

## 验收清单

- [ ] 所有按钮点击有按压 + 波纹 + 状态反馈
- [ ] 弹窗打开/关闭都有完整动画，液态玻璃首帧不延迟
- [ ] 页面路由切换有明确转场，顶栏不闪
- [ ] 更多菜单/右键菜单可开可关，关闭不闪
- [ ] 批量栏进出场
- [ ] 抽屉/详情/Agent/照片详情动画一致且可打断
- [ ] 滑块拖动有填充/数值脉冲
- [ ] 设置分区导航有 active 滑块 + 滚动联动
- [ ] 滚动有进度与边缘提示
- [ ] 异步操作有低干扰处理指示
- [ ] 减少动态/关闭动效时完全静止
- [ ] 无控制台异常、无布局抖动、无 WebView2 玻璃首帧问题
- [ ] 3 个子代理独立签字

## 审查门

1. **代码审查子代理**：检查 JS/CSS 实现、可打断性、内存/监听器泄漏、reduced-motion、WebView2 兼容。
2. **浏览器交互子代理**：实际跑 Playwright，逐项点击/切换/关闭，检查动画完整性、无闪烁、无卡死、控制台干净。
3. **设计与可用性子代理**：检查节奏、层级、反馈是否过度、焦点/可读性、与拾影液态玻璃风格一致性。

三个子代理均给出“通过”后才交付。
